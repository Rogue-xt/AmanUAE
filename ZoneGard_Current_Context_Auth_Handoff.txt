IMPORTANT ARCHITECTURE DECISIONS
1. Vehicles page is list/management entry point.
   - Add Vehicle happens here.
   - Vehicle cards show View/Edit.
   - Delete should be on vehicle details page, not list, to reduce accidental destructive actions.

2. Vehicle details page is the main vehicle workspace.
   - Shows vehicle image, plate, emirate.
   - Edit Vehicle implemented using reusable VehicleEditModal.
   - Delete Vehicle implemented/desired here.
   - Shows linked documents.
   - Document actions should work here: View, Share, Edit, Renew, Vehicle Link/Unlink, Delete.
   - Nav title should show vehicle label using <Stack.Screen options={{ title: vehicle?.label || "Vehicle Details" }} />.

3. DocumentEditModal should stay focused only on document fields.
   - Title
   - Expiry date with DateTimePicker
   - Replace/Renew file
   - It should NOT handle vehicle link/unlink.

4. DocumentVehicleLinkModal is separate and reusable.
   - Used in Vault.
   - Used in Vehicle Details.
   - Future: Document Details page.

2. components/documents/DocumentVehicleLinkModal.tsx
Purpose:
- Reusable modal to link/unlink a document to a vehicle.
Props:
- visible
- document: DocumentRecord | null
- vehicles: VehicleProfile[]
- onClose
- onLink(documentId: string, vehicleId: string | null)
Behavior:
- Preselects current document.vehicleId
- Shows current link
- Lists vehicles
- Unlink sets selectedVehicleId to null
- Save calls onLink
Usage in Vault:
<DocumentVehicleLinkModal
  visible={!!linkingDocument}
  document={linkingDocument}
  vehicles={vehicles}
  onClose={() => setLinkingDocument(null)}
  onLink={async (docId, vehicleId) => {
    await updateDocument(docId, { vehicleId: vehicleId ?? "" });
    setLinkingDocument(null);
  }}
/>

AUTH / FIREBASE NEXT MODULE
User requested authentication so data is not lost when app is uninstalled.
Decision: Use Firebase, not Clerk.
Reason:
- Firebase Auth + Firestore + future Storage/FCM are a complete mobile backend.
- Clerk is auth only; would still need database/storage separately.
- Firebase Spark plan should be enough for MVP.
- Keep AsyncStorage as local cache; use Firestore as cloud backup/restore.

Firebase current status:
- firebase package installed.
- Firebase project/config file created.
- Next step: create AuthContext and gate app.
